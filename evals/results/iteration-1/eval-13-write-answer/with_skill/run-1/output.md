# git merge와 git rebase의 차이

두 명령은 모두 한 브랜치의 변경을 다른 브랜치에 합칩니다. 차이는 커밋 기록을 남기는 방식에 있습니다. merge는 갈라진 두 기록을 그대로 두고, 합친 지점에 새 커밋을 하나 만듭니다. rebase는 내 커밋을 대상 브랜치의 끝으로 옮겨서 다시 쌓습니다.

예를 들어 `main`에서 `feature` 브랜치를 만들고 커밋 C와 D를 올렸다고 해 봅시다. 그동안 다른 사람이 `main`에 커밋 E를 올렸습니다.

```
      C---D  feature
     /
A---B---E    main
```

## merge

`main`에서 `git merge feature`를 실행하면 Git은 두 갈래를 합친 merge 커밋 M을 만듭니다.

```
      C---D
     /     \
A---B---E---M  main
```

기존 커밋은 하나도 바뀌지 않습니다. 브랜치가 언제 갈라지고 언제 합쳐졌는지가 기록에 그대로 남습니다. 대신 브랜치가 많으면 기록이 여러 갈래로 얽혀서 읽기 어려워질 수 있습니다.

## rebase

`feature`에서 `git rebase main`을 실행하면 Git은 C와 D를 E 뒤에 다시 적용합니다.

```
A---B---E---C'---D'  feature
```

기록이 한 줄로 이어져서 읽기 쉽습니다. 하지만 C'와 D'는 C, D와 내용이 같아도 해시가 다른 새 커밋입니다. rebase는 기록을 새로 쓰는 명령입니다.

그래서 다음 규칙을 꼭 지켜야 합니다. **이미 원격에 올려서 다른 사람이 받아 간 커밋은 rebase하지 않습니다.** 내 기록과 동료의 기록이 서로 달라져서 충돌이나 중복 커밋이 생깁니다.

## 충돌을 해결하는 방식

merge에서는 충돌을 한 번에 해결하고 merge 커밋을 만듭니다. rebase는 커밋을 하나씩 다시 적용하기 때문에 커밋마다 멈출 수 있습니다. 충돌을 해결한 뒤 `git add`를 하고 `git rebase --continue`로 다음 커밋으로 넘어갑니다. 중간에 그만두려면 `git rebase --abort`를 실행합니다. 그러면 rebase를 시작하기 전 상태로 돌아갑니다.

## 언제 무엇을 쓰나

혼자 쓰는 작업 브랜치를 최신 `main`에 맞출 때는 보통 rebase를 씁니다. 여러 사람이 함께 쓰는 브랜치를 합칠 때는 merge를 씁니다. 팀마다 정한 규칙이 다를 수 있으니 처음에는 팀의 규칙을 먼저 확인하세요.
