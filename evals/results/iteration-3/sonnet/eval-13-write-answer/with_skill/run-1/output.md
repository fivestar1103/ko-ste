# git merge와 git rebase의 차이

두 명령은 모두 다른 브랜치의 변경을 내 브랜치에 가져옵니다. 차이는 그 결과로 남는 히스토리입니다.

## merge: 두 히스토리를 합칩니다

`feature` 브랜치에서 `git merge main`을 실행하면 git은 두 브랜치의 끝을 합치는 병합 커밋을 하나 만듭니다. 기존 커밋은 바뀌지 않습니다. 누가 언제 어느 브랜치에서 작업했는지가 그대로 남지만, 병합이 잦아지면 히스토리에 갈래가 많아져 읽기 어려워집니다.

```
git switch feature
git merge main
```

## rebase: 내 커밋을 새 기준 위로 옮깁니다

`git rebase main`을 실행하면 git은 `feature`에서 만든 커밋을 `main`의 최신 커밋 뒤에 하나씩 다시 적용합니다. 히스토리가 한 줄로 이어져 읽기 쉽습니다. 다만 다시 적용된 커밋은 내용이 같아도 새 커밋이므로 커밋 해시가 바뀝니다.

```
git switch feature
git rebase main
```

## 어떤 것을 쓰나

- 이미 원격에 올려 다른 사람이 쓰는 브랜치는 rebase하지 않습니다. 해시가 바뀐 히스토리를 올리려면 강제 푸시가 필요하고, 같은 브랜치를 받은 동료의 히스토리와 어긋납니다.
- 아직 나만 쓰는 로컬 브랜치는 rebase로 정리해도 됩니다.
- 히스토리를 그대로 남기고 싶거나 rebase가 부담스러우면 merge를 씁니다.

어느 쪽을 쓸지는 팀마다 규칙이 다를 수 있으니, 작업 전에 팀의 방식을 확인하세요.
