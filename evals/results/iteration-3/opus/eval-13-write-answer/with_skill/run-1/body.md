# git rebase와 git merge의 차이

두 명령은 모두 한 브랜치의 변경을 다른 브랜치에 합칩니다. 차이는 합친 뒤 커밋 기록이 어떤 모양으로 남는지에 있습니다.

예를 들어 `main`에서 `feature` 브랜치를 만들어 작업하는 동안 다른 사람이 `main`에 새 커밋을 올렸다고 해 봅시다. 이제 두 브랜치는 서로 다른 방향으로 갈라져 있습니다.

`git merge`는 두 브랜치의 기록을 그대로 두고, 두 갈래를 잇는 머지 커밋을 새로 만듭니다.

```
git switch feature
git merge main
```

기존 커밋은 바뀌지 않습니다. 그래서 언제 브랜치가 갈라지고 언제 합쳐졌는지가 기록에 남습니다. 대신 머지가 잦으면 기록이 여러 갈래로 얽혀 읽기 어려워질 수 있습니다. 브랜치가 갈라지지 않은 상태라면 Git은 머지 커밋 없이 브랜치 포인터만 앞으로 옮깁니다. 이를 fast-forward라고 합니다.

`git rebase`는 `feature`의 커밋을 떼어 내서 `main`의 최신 커밋 뒤에 하나씩 다시 적용합니다.

```
git switch feature
git rebase main
```

결과는 처음부터 최신 `main` 위에서 작업한 것처럼 한 줄로 이어진 기록입니다. 머지 커밋이 생기지 않아 기록을 따라 읽기 쉽습니다. 하지만 다시 적용된 커밋은 내용이 같아도 해시가 다른 새 커밋입니다. 즉 rebase는 기존 기록을 바꿉니다. 충돌이 나면 커밋마다 따로 해결해야 할 수도 있습니다.

**다른 사람과 이미 공유한 커밋은 rebase하지 않습니다.** 원격 저장소에 push한 커밋을 rebase하면 다른 사람이 가진 기록과 내 기록이 어긋납니다. 그러면 강제 push(`git push --force`)가 필요하고, 다른 사람의 작업이 꼬일 수 있습니다. rebase는 아직 나만 가진 로컬 브랜치를 정리할 때 쓰는 것이 안전합니다.

어느 쪽을 쓸지는 팀마다 정한 규칙이 다릅니다. 기록을 있는 그대로 남기려면 merge를 쓰고, 한 줄로 정리된 기록을 원하면 rebase를 씁니다. 처음 합류한 팀이라면 먼저 그 팀의 규칙을 확인하세요.
