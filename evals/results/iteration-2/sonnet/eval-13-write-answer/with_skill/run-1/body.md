# git rebase와 git merge의 차이

두 명령은 모두 한 브랜치의 변경을 다른 브랜치에 합칩니다. 다른 점은 합친 뒤 남는 히스토리의 모양입니다.

`main`에서 `feature` 브랜치를 따서 작업하는 동안 `main`에도 새 커밋이 생겼다고 해 봅시다.

## merge

```
git switch feature
git merge main
```

merge는 두 브랜치의 끝을 합치는 새 커밋(머지 커밋)을 만듭니다. 기존 커밋은 하나도 바뀌지 않습니다. 언제 어떻게 합쳤는지가 히스토리에 그대로 남습니다. 대신 머지 커밋이 쌓이면 히스토리가 갈라졌다 합쳐지는 모양이 되어 읽기 어려워집니다.

## rebase

```
git switch feature
git rebase main
```

rebase는 `feature`의 커밋을 `main`의 최신 커밋 뒤로 옮겨서 다시 만듭니다. 히스토리가 한 줄로 이어져 읽기 쉽습니다. 대신 옮겨진 커밋은 내용이 같아도 새 커밋이므로 해시가 바뀝니다. 즉 rebase는 히스토리를 다시 쓰는 작업입니다.

## 무엇을 쓸까

- 이미 원격에 푸시해서 다른 사람이 쓰는 브랜치는 rebase하지 않습니다. 해시가 바뀌면 동료의 로컬 히스토리와 어긋나 충돌이 생깁니다.
- 내 로컬에서만 쓰는 브랜치는 rebase로 정리해도 됩니다. 푸시하기 전에 최신 `main` 위로 올려 두면 PR의 히스토리가 깔끔해집니다.
- 히스토리를 있는 그대로 남기고 싶거나 어느 쪽이 안전한지 헷갈리면 merge를 씁니다. merge는 기존 커밋을 바꾸지 않아서 더 안전합니다.

팀마다 정한 규칙이 있는 경우가 많으니, 먼저 팀의 브랜치 전략을 확인하세요.
