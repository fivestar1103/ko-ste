## 판정: 대체로 양호하며 일부 수정 권장

원문:
> 파일을 저장할 수 없습니다. 디스크 공간이 부족하거나 쓰기 권한이 없을 수 있습니다. 관리자에게 문의하십시오.

### 잘된 점
- 문장이 짧고, 문장마다 하나의 내용만 담고 있습니다.
- 첫 문장에서 결과(저장 실패)를 바로 알려 줍니다.
- 합니다체를 끝까지 일관되게 사용합니다.
- 사용자를 탓하는 표현이 없습니다.

### 지적 사항 (엄격 기준)

| # | 위치 | 문제 | 권장 |
|---|---|---|---|
| 1 | 두 번째 문장 | "~거나 ~ㄹ 수 있습니다"가 원인 두 개를 한 문장에 넣고 추측으로 끝납니다. 사용자는 무엇을 먼저 확인할지 알 수 없습니다. | 원인을 나누고, 확인할 행동으로 바꿉니다. |
| 2 | 세 번째 문장 | 디스크 공간은 사용자가 직접 해결할 수 있는데, 처음부터 관리자에게 넘깁니다. | 사용자가 할 수 있는 조치를 먼저 쓰고, 관리자 문의는 마지막 단계로 둡니다. |
| 3 | 전체 | 어떤 파일을 어디에 저장하다 실패했는지 알 수 없습니다. | 파일 이름이나 경로를 함께 보여 줍니다. |
| 4 | "쓰기 권한이 없을" | 부정형이라 무엇을 확인해야 하는지 바로 떠오르지 않습니다. | "쓰기 권한이 있는지 확인하십시오"처럼 긍정형 지시로 씁니다. |

### 수정안

**A. 원인을 구분할 수 없는 경우**
```
파일을 저장할 수 없습니다: {파일 경로}
다음을 확인하십시오.
1. 디스크에 빈 공간이 충분한지 확인하십시오.
2. 이 폴더에 쓰기 권한이 있는지 확인하십시오.
문제가 계속되면 관리자에게 문의하십시오.
```

**B. 프로그램이 원인을 구분할 수 있는 경우 (권장)**

원인별로 메시지를 따로 보여 주면 추측하는 표현이 필요 없습니다.
```
파일을 저장할 수 없습니다. 디스크 공간이 부족합니다.
불필요한 파일을 삭제한 후 다시 저장하십시오.
```
```
파일을 저장할 수 없습니다. 이 폴더에 쓰기 권한이 없습니다.
다른 폴더에 저장하거나 관리자에게 권한을 요청하십시오.
```

### 요약
원문을 그대로 써도 큰 문제는 없습니다. 다만 엄격 기준으로 보면 사용자가 할 조치가 불명확하고 관리자 문의가 너무 이릅니다. 원인을 구분할 수 있다면 B안을, 구분할 수 없다면 A안을 권장합니다.
