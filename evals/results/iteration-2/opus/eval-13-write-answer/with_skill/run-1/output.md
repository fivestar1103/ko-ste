# git rebase와 git merge의 차이

두 명령은 모두 한 브랜치의 변경을 다른 브랜치에 합칠 때 씁니다. 차이는 합친 뒤에 커밋 기록이 어떤 모양이 되는지에 있습니다.

`feature` 브랜치에서 작업하는 동안 다른 사람이 `main`에 새 커밋을 올렸다고 가정하겠습니다. 이제 `main`의 변경을 `feature`에 반영해야 합니다.

## merge

```
git switch feature
git merge main
```

merge는 두 브랜치의 기록을 그대로 두고, 둘을 잇는 머지 커밋을 새로 하나 만듭니다. 기존 커밋은 바뀌지 않습니다. 그래서 언제 브랜치가 갈라졌고 언제 합쳐졌는지가 기록에 그대로 남습니다. 대신 브랜치가 많으면 기록이 여러 갈래로 얽혀서 `git log --graph`가 읽기 어려워질 수 있습니다.

## rebase

```
git switch feature
git rebase main
```

rebase는 `feature`의 커밋을 떼어 내서 `main`의 최신 커밋 뒤에 하나씩 다시 적용합니다. 결과로 기록이 한 줄로 이어집니다. 처음부터 최신 `main` 위에서 작업을 시작한 것처럼 보입니다.

이때 다시 적용된 커밋은 내용이 같아도 새 커밋입니다. 커밋 해시가 바뀝니다. rebase가 기록을 다시 쓴다고 말하는 이유가 이것입니다.

## 주의할 점

**이미 push해서 다른 사람과 함께 쓰는 커밋은 rebase하지 마세요.** 내 쪽의 커밋 해시가 바뀌면 다른 사람이 가진 기록과 어긋납니다. 이 상태로 강제 push를 하면 동료의 작업이 꼬이거나 사라질 수 있습니다.

충돌을 처리하는 방식도 다릅니다. merge에서는 충돌을 한 번에 해결합니다. rebase에서는 커밋을 하나씩 다시 적용하므로, 같은 부분에서 충돌이 커밋마다 반복될 수 있습니다.

## 언제 무엇을 쓰나

아직 나만 쓰는 로컬 브랜치를 최신 `main`에 맞출 때는 rebase를 많이 씁니다. 공유된 브랜치를 합칠 때나 합친 시점을 기록에 남기고 싶을 때는 merge를 씁니다. 팀마다 정한 규칙이 있는 경우가 많으니 먼저 팀의 방식을 확인하세요.
